# Alexa Voice Events v0.2.0

Configure generic voice events in Home Assistant and let HA decide phrases,
household actions, reply text and speakers. This release adds:

- Optional interruption of the source speaker using official Alexa Devices Stop.
  It defaults **on** and can stop music; blank reply text does not disable it.
- Reply text evaluated after household Actions, sent through official Speak or
  optional Announce. Reply to the source or one explicitly selected speaker.
- Read-only `alexa_voice_events.resolve_targets` for account/device-bound official
  targets. It does not speak, authenticate again or contact Amazon.
- Event/session/account/age checks before managed steps, with rejection reasons
  available in automation traces. Household rules remain in HA.

## Installation and migration

Use **Core 2026.10.2** and **aioamazondevices 16.3.2**. Install the tagged component
through HACS custom repositories or the
[source archive](https://github.com/vincent97277/ha-alexa-voice-events/archive/refs/tags/v0.2.0.zip).
There is no custom binary asset. GitHub's source ZIP/tarball contain the repository;
copy only `custom_components/alexa_voice_events` for a manual component install.

**Update the Blueprint separately** from the
[v0.2.0 Blueprint](https://github.com/vincent97277/ha-alexa-voice-events/blob/v0.2.0/blueprints/automation/alexa_voice_events/phrase_to_action.yaml).
Back up actual component/Blueprint files and automation configs/enabled states
before replacing them. Keep the same imported path; do not create duplicate phrase
consumers. See [configuration and rollback](../replies.md#migration-and-rollback).
The [v0.1.0 source](https://github.com/vincent97277/ha-alexa-voice-events/releases/tag/v0.1.0)
remains available, but rollback also requires the original Blueprint and automations.

## Evidence and limits

Python runtime files and the Blueprint match fixed hardware candidate
`e5fd04015b3bc3349da48abf702e3bc2f3f37ea4`. Only package version metadata and
release documentation change. Candidate manual installation and a tagged HACS
installation are separate evidence; this release does not claim a new HACS hardware
install. Automated validation covers 98 tests, mypy and Ruff; GitHub Checks must pass
on the exact release commit before publication.

- **Scoped passes:** source Speak and existing household actions each have three
  consecutive complete/correct outcomes with acceptable response; unmatched native
  requests remained normal. See the [hardware report](../hardware-acceptance.md).
- **Unreliable interruption:** matched queries can produce an HA reply while native
  answers or Follow-Up continue. A successful Stop service call is not confirmation
  that native dialogue ended.
- **Submitted audio cannot be recalled:** HA speech already started may finish first,
  with a newer native answer afterward. The Blueprint drops superseded work at its
  next guard only while that work is still unsent; it cannot detect utterances whose
  history has not reached HA or retract upstream commands.
- **No delivery/finished-speaking receipt:** local return means called/enqueued.
  The upstream client has its own HTTP retries. There is no extra Blueprint retry,
  text-command fallback, fixed speech wait, global speaker scheduler or music recovery.
- **Scheduling:** queued execution is per automation. Overlapping phrase automations
  may each run, and cross-automation/shared-target audio can overlap.
- **Unverified:** Announce, active-media side effects, other speakers and cross-speaker
  physical results. Self-recognition and non-speech volume observations are bounded
  windows, not certification of every push callback or long-term behavior.
