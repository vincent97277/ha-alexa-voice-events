# Alexa Voice Events v0.3.0

This minor release simplifies replies while keeping household rules in HA.

- Select **Sensors to report** to generate a reply without writing Jinja. Reports
  use HA-recorded names, values and units after household Actions. Missing/invalid
  measurements and non-finite values are unavailable; true zero remains valid.
- Optional **Reply message** text/templates override sensor reports. Clear both
  fields for silence; the independent interruption switch still defaults on.
- Replies always use normal Speak on the triggering speaker. **Reply speaker and
  Reply mode are removed**, including the advanced Announce selector. Existing
  saved reply-device/mode values no longer control this Blueprint; migrate any
  consumers that relied on them before updating. Advanced HA actions and the
  read-only target resolver API remain available.
- Phrase guidance explains meaningful context and literal matching, and separates
  missing transcripts, unmatched phrases and submitted-but-incomplete speech.
  No transcript correction, playback retry, fixed delay or new login is introduced.

## Install, migrate and roll back

Requires **Core 2026.10.2** and **aioamazondevices 16.3.2**. Use the
[v0.3.0 source ZIP](https://github.com/vincent97277/ha-alexa-voice-events/archive/refs/tags/v0.3.0.zip)
or HACS custom repository. There are no custom assets; GitHub provides source
ZIP/tarball downloads. Manual component installs copy only
`custom_components/alexa_voice_events`.

**Update the imported Blueprint separately** from the
[same tag](https://github.com/vincent97277/ha-alexa-voice-events/blob/v0.3.0/blueprints/automation/alexa_voice_events/phrase_to_action.yaml).
Save actual prior component/Blueprint files, automation configs and enabled states;
disable overlapping consumers, replace at the original path, remove obsolete
inputs, validate and verify one consumer at a time. See
[setup and rollback](https://github.com/vincent97277/ha-alexa-voice-events/blob/v0.3.0/docs/replies.md#migration-and-rollback).
The [v0.2.0 release](https://github.com/vincent97277/ha-alexa-voice-events/releases/tag/v0.2.0)
is retained; rollback requires saved settings as well as source files.

## Validation and limits

The Blueprint is unchanged from hardware candidate
`88ad0288cfd1a28735fcd2d3d61b5935514f8bd4`; Python behavior is unchanged from
v0.2.0, with version metadata updated to 0.3.0. The candidate Blueprint was
installed manually, not as a new tagged HACS component installation.

[Scoped Uxbridge checks](https://github.com/vincent97277/ha-alexa-voice-events/blob/v0.3.0/docs/hardware-simplified-replies.md)
cover three complete sensor reports, three complete existing template replies,
three corrected lights-off/on rounds and three normal unmatched native queries.
Initial lighting failures were retained in the report: the household needed
observed literal variants without the wake word. This was not a core ASR fix.
Software validation covers 111 tests, mypy and Ruff. Main CI must pass on the exact
release commit before tagging, and tag CI before formal release creation.

Native-answer/follow-up interruption remains unreliable. Earlier matched-Speak
incomplete-audio reports remain unresolved and are outside this release's fix
scope. A local service return is not cloud delivery or playback completion;
submitted commands cannot be recalled. Other speakers, every unavailable-value
spoken branch, Announce and active-media effects were not newly verified. Three
successes establish scoped observations, not a long-term reliability rate.
